# Implementation contract addendum

Approved by the user in this conversation on 7 September 2026. Applies only to the six resolved gaps; the original SRS remains authoritative elsewhere. Capability count remains twelve.

1. **Citizen analysis:** dedicated `/citizen/scans/{id}/analysis`, `/citizen/analysis/{id}`, `/citizen/scans/{id}/result` APIs. Ownership is an immutable nullable `cases.citizen_session_id`. Only citizen-origin images and public-safe preliminary values are returned. Departmental data never enters this response projection. Tracking uses a separate cryptographically random token stored as a hash.
2. **Capture configuration:** assigned Inspectors can change the capture profile before evidence registration using `PATCH /cases/{id}/capture-profile`. `POST /cases/{id}/coverage-confirmations` records Other Package inspected areas, source IDs, reason, officer and server time. Physical coverage is computed from usable physical captures and explicit search regions; listing/government uploads never satisfy it. EVD-03 accepts the full retained local evidence ID manifest and validates each acknowledged item.
3. **Priority:** `PATCH /cases/{id}/priority` is Government-only. `HIGH/NORMAL/LOW` are prototype bands. Computed band/reasons remain persisted in `cases.priority_reasons`; the override and its previous value are append-only audit events. The equal rule rank 1 baseline in the approved proposal is non-statutory; recurrence and evidence readiness break ties.
4. **Briefs:** drafts and edits persist in existing `audit_events` as complete version snapshots, including creator/editor/source references. Each draft's event ID identifies immutable content. `POST /inspection-briefs/{id}/approval` records separate Government APPROVE/REJECT. Vocabulary: DRAFT, APPROVED, REJECTED. Editing produces a new DRAFT requiring fresh approval. Assigning using a brief requires an approved exact draft ID and matching context. Copilot has no approval/assignment tool.
5. **Follow-ups:** ASSIGNED → IN_PROGRESS → COMPLETED. Same-state repetition is idempotent; skipping/backward transitions are rejected. Government or assigned Inspector only. Existing `followups` and audit history store the operation.
6. **Declaration reviews:** `POST /cases/{id}/declarations/{group}/verification` accepts ACCEPT/CORRECT/REJECT, reason and source refs. Store previous/extracted value, selected/corrected value, reviewer/time and source refs in append-only audit events. OCR candidates remain immutable. A reviewed declaration is not a verified finding. Finding decisions continue through VER-01 and `verification_events`.

The report action is the Inspector's explicit completion request. It requires successful analysis, no pending potential findings, and a declaration review for every required declaration. Unresolved evidence blocks a final completed report. Source-supported passes are reported as reviewed evidence, never as legal certification. Rejected recommendations are listed in verification history, not the verified-findings section. Only accepted/corrected findings with verification events enter that section and pattern counts.

An inspection based on a citizen lead continues on the same existing case root; assignment does not turn a citizen observation into Inspector evidence. Public results always filter by source type. Officer-confirmed snapshot fields and accepted findings from field evidence are independently required for pattern eligibility.

API schemas document technical file retrieval and list projections needed by the specified screens. Authenticated evidence bytes are served by `GET /evidence/{id}/content`; reports by RPT-02 with `format=pdf|docx`. Both enforce the original access policy. Brief edits use COP-03 with the preceding draft ID and edited content. These use the same backend and existing models.

Legal fixture thresholds/placement zones are not inferred from arbitrary packages. Rules store SRS reference families and an explicit prototype fixture version. Presentation fixtures are engineering demonstrations, clearly labelled, and cannot establish a universal statutory threshold. A consolidated legal-source freeze remains required before any claim of legally validated deployment.

Every tunable is in `seed/prototype-config.json`; every departure from measured calibration is reported in `docs/VALIDATION.md`. Package-manager or Android SDK installation failures must not be described as successful builds.
